Project 2

Ask Hey Stupid — Production AWS Application

A public-facing serverless AI application using AWS edge, API, compute, and AI services. The project includes CloudFront routing, WAF protections, API Gateway, Lambda, Amazon Bedrock, CORS debugging, and production-style troubleshooting.

Browser │ ▼ CloudFront ├── Static site traffic → S3 private origin with OAC │ └── API traffic /prod/ask* → API Gateway │ ▼ Lambda │ ▼ Amazon Bedrock

Security Controls

  • CloudFront in front of static and API paths.
  • S3 origin protected using Origin Access Control.
  • AWS WAF attached for edge protection.
  • Rate-based rules for abuse protection.
  • Managed rule groups for common web threats.
  • CORS and preflight testing through CloudFront and API Gateway.

Engineering Work

  • Built static frontend delivery through CloudFront.
  • Integrated API Gateway with Lambda backend.
  • Connected Lambda to Amazon Bedrock model invocation.
  • Debugged 403, 4xx, CORS, and missing token behavior.
  • Used CloudWatch logs and curl testing for validation.
  • Improved reliability through structured troubleshooting.
CloudFront S3 OAC AWS WAF API Gateway Lambda Amazon Bedrock CORS CloudWatch Logs Serverless Security

Terraform Root Module │ ├── modules/logging │ └── audit/logging resources │ ├── modules/security │ └── WAF and edge security controls │ ├── modules/frontend │ └── S3 + CloudFront static site delivery │ └── modules/backend └── Lambda + API Gateway + Bedrock integration

Terraform Skills Demonstrated

  • Modular Terraform project structure.
  • Reusable frontend, backend, logging, and security modules.
  • AWS provider aliasing for CloudFront/WAF requirements.
  • S3 bucket configuration with public access blocking.
  • CloudFront distribution provisioning.
  • Lambda packaging and deployment troubleshooting.

Why This Matters

  • Security controls can be reviewed before deployment.
